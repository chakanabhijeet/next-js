## 1. Architecture in One Minute

The `features/` folder follows an **MVVM pattern**. Every feature is split the same way:

| Layer | Folder | Responsibility |
|---|---|---|
| **Model** | `models/` | Shape and normalisation of data (what a Production, Product, User looks like). Also holds validation rules (`*.schema.js`) |
| **Service** | `services/` | API calls only. No UI, no state |
| **View-Model** | `view-models/` | React hooks (`use-...-view-model.js`) holding logic, state, grouping and calculations for a screen |
| **View** | `views/` | Pure UI (`.jsx`) that renders what the view-model gives it |
| **Store** | `store/` | Global client state (auth only) |

Pages in `src/app/` stay thin: they pick a view-model and render a view or cards.

**Guards** (in `components/common/`) decide who may see a page:

| Guard | Used on | Rule |
|---|---|---|
| `AuthGuard` | Every page inside `DashboardLayout` | Logged-out users are sent to the login page |
| `GuestGuard` | The login page `/` | Logged-in users are sent to the dashboard |
| `SuperAdminGuard` **NEW** | Registration page (currently switched off) | Only a Super Admin sees the page |

## 2. Pages at a Glance

| Route | File | What it shows | Who can open it |
|---|---|---|---|
| `/` | `app/page.js` | Login screen | Logged-out users (logged-in users are redirected) |
| `/dashboard` | `app/dashboard/page.js` | Live machine cards, date picker, detail popup | Logged-in users |
| `/monitoring` | `app/monitoring/page.js` | Hourly production charts | Logged-in users |
| `/tv` | `app/tv/page.js` | TV display, no sidebar, slides rotate every 35 sec | See note below |
| `/employees/create` **NEW** | `app/employees/create/page.js` | Register a new person (name, ID, department, role, password) | Any logged-in user for now. Intended: Super Admin only |
| `/dashboard/products` | `app/dashboard/products/page.js` | Products | Logged-in users |
| `/dashboard/settings` | `app/dashboard/settings/page.js` | Settings | Logged-in users |

> **TV page:** it has no sidebar. Check whether it should be wrapped in `AuthGuard`
> too, or left open on purpose for the display screen.
